# Cafe Bazaar release-readiness checklist

## Android candidate

- Application ID: `com.antivirusalai`
- Candidate version: `0.4.0`, versionCode `4`
- minSdk 26; targetSdk 36
- Cafe Bazaar billing: official Poolakey SDK 2.3.0
- Subscription products expected in Pishkhan: `alai_plus_monthly` and `alai_plus_annual`

## Pishkhan and Developer API configuration (account-owner actions)

1. Create the two auto-renewing subscription products using the exact SKU identifiers above.
2. Configure localized price, regional availability, trial offers and billing terms in Pishkhan. Prices and eligible trial duration are queried at runtime; the app does not hardcode them.
3. Create/authorize a Developer API client for this app and obtain its Client ID, Client Secret and Refresh Token.
4. Configure Worker secrets: `BAZAAR_CLIENT_ID`, `BAZAAR_CLIENT_SECRET`, `BAZAAR_REFRESH_TOKEN`, `PLUS_ENTITLEMENT_HMAC_SECRET`, and `RATE_SALT`. Keep all values outside GitHub source, app assets, and chat.
5. Apply `cloud-api/migrations/0001_bazaar_billing.sql` to the Worker D1 database.
6. Verify `GET /v1/billing/bazaar/status` returns `checkoutReady: true` and both expected SKUs, then deploy the Worker after reviewing the configuration.
7. Test a valid new purchase, restore after reinstall, canceled-but-still-valid subscription, expired/refunded token, wrong product, invalid token, Bazaar outage, missing credentials and ineligible trial account.

## App and security validation

- The Free tier must keep working without Bazaar installed or network connectivity: local scanning, evidence reports and encrypted quarantine.
- PLUS hash reputation requires explicit consent and a short-lived, server-signed token. Only SHA-256 and normal request metadata are sent; file contents, filenames and paths are not uploaded.
- The Worker verifies the subscription token server-side and stores only the purchase token digest.
- A no-match in the current reputation database is UNKNOWN, never a "clean" verdict.
- Verify All files access, package-inventory visibility, foreground-service disclosures and limited behavior when permissions are denied against current Android and Cafe Bazaar review rules.
- Publish an accessible Persian privacy policy, support contact, accurate listing text/screenshots and complete the marketplace's age/content and privacy declarations.
- Do not claim guaranteed removal, full real-time interception, a production ML detector or a production malware signature feed. Those capabilities have not yet been independently validated.

## Signing and submission

- Debug APK and unsigned AAB preflight are not final store artifacts.
- Build a production-signed release AAB with the owner's protected signing key. Keep at least two encrypted backups of the keystore and record its alias; every future update of this package must use the same signing identity unless a documented key-rotation process is followed.
- Cafe Bazaar's AAB upload flow requires the signed bundle and its corresponding `.bin` generated by the official Cafe Bazaar bundle signer. The current official tool example is `bundlesigner-0.1.14.jar`; its project documents the `genbin` command and signing flags at https://github.com/cafebazaar/bundle-signer.
- Run the signer locally (never in a public CI job and never with the keystore committed):
  ```sh
  java -jar bundlesigner-0.1.14.jar genbin -v \
    --bundle app-release.aab \
    --bin ./cafebazaar-bin/ \
    --v2-signing-enabled true \
    --v3-signing-enabled false \
    --ks /secure/local/path/antivirus-al-ai-release.jks \
    --ks-key-alias "$ALAI_RELEASE_KEY_ALIAS" \
    --ks-pass env:CAFEBAZAAR_KEYSTORE_PASSWORD \
    --key-pass env:CAFEBAZAAR_KEY_PASSWORD
  ```
  Set the password environment variables only in the trusted local shell or password manager. Do not place their values in the command, repository, build log, issue, or chat.
- Upload both the signed `.aab` and its generated `.bin` in the Pishkhan release flow. Verify the application ID, versionCode, signer identity, artifact SHA-256 values and install/upgrade behavior on real devices before submission.

## Not performed by repository automation

This code change does not create Pishkhan products, prices or trial offers; authorize a Developer API client; obtain OAuth credentials; set Cloudflare secrets; apply a remote D1 migration; deploy the Worker; publish a privacy-policy website; or sign the release bundle. Those operations require the authorized account owner.
